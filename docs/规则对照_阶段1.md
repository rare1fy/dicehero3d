## 1. 战斗开始和回合结构

### 1.1 层数与数值缩放
- **原版**：
  - 巫妖是第 1 章的中 Boss，固定在 **depth 7**（`config/balance/world.ts:54,66`）。从本章 `bossRank:'mid'` 的几只 Boss 里随机抽一只（`data/enemies.ts:95-107`）。
  - 缩放公式：hpScale = `DEPTH_SCALING[7].hpMult (1.80)` × `enemyHpMultiplier (1.0)` × 第 1 章 hpMult (1.0)；dmgScale = `1.00` × 1.0（`hooks/useBattleLifecycle.ts:78-81`、`data/enemies.ts:153-165`、`config/balance/player.ts:22-45`、`config/balance/world.ts:98-104`）。
  - `enemyHpMultiplier` 只有拿到「diceCount」战利品时才 +0.25（`logic/lootProcessor.ts`，diceCount 分支）。
  - Boss 节点只有 Boss 一波，没有前置小怪（`data/enemies.ts:158-166`）。
  - `buildEnemy`：hp = floor(baseHp×hpScale)，attackDmg = floor(baseDmg×dmgScale)。caster 初始距离 3，warrior/guardian 初始距离 2（`data/enemies.ts:57-79`）。
  - 算出来：**巫妖最大 HP 216，attackDmg 10**。
- **v6**：
  - `DEPTH_SCALING` 表逐项相同（`03_rules.js:221`）。`buildEnemy` 同公式（`03_rules.js:226-229`）。
  - Boss 节点按 `node.depth>=12` 选终 Boss 或中 Boss（`03_rules.js:246`）。`G.depth = n.depth`（`05_meta.js:110`）。
  - 没有章节倍率和 `enemyHpMultiplier`（第 1 章都是 1.0）。
- **结论**：**一致**，前提是切片把 depth 设成 7。另外，原版 depth<0 时返回 `{0.9, 0.8}`，v6 会钳到 depth 0（`{0.9, 0.4}`），本场用不到。

### 1.2 depthBonus（层数对骰子加成的影响）
- **原版**：
  - depth 取当前地图节点的深度（`logic/diceOnPlay/index.ts:69-71`、`logic/diceOnPlay/warriorCalc.ts:28-29`）。
  - `depthDmgBonus = 1 + floor(depth/3)×0.15`，作用在 `bonusDamage` 上：ceil(bonusDamage × depthDmgBonus)（`index.ts:74-76`）。
  - `depthMultBonus = floor(depth/5)×0.05`，作用在 `bonusMult` 上（`index.ts:77`）。
  - `aoeDamage` 不吃加成（`warriorCalc.ts:60`）。
  - depth 7 时：伤害 ×1.30，倍率 +0.05。所以**血之渴望 +11，泰坦之拳 +20，旋风斩 +6**。本场的骰子里没有 bonusMult 类。
- **v6**：`depthBonus()` 同公式（`03_rules.js:108`），使用处 `03_rules.js:148-149,162`。
- **结论**：**一致**。

### 1.3 骰袋初始化与第一回合
- **原版**：
  - 开战时把拥有的骰子全部 Fisher-Yates 洗一遍作为骰袋，弃骰为空（`data/diceBag.ts:15-22,90-93`、`logic/battleInit.ts:57-58`）。
  - 第一回合抽 min(6, drawCount + challengeDrawBonus) = 3 颗（`hooks/useBattleLifecycle.ts:197-206`）。
  - `rerollCount=0`（`:215`）。
  - `battleTurn=1`，玩家状态清空，护甲 = levelStartArmor（升级奖励，初始为 0），收割槽全部清零（`logic/battleInit.ts:37-41,69-76`）。
- **v6**：`bag: shuffle(G.owned)`、`battleTurn:1`、`G.statuses=[]`（`04_battle.js:24-31`），然后进第一回合抽 3 颗（`04_battle.js:141-175`）。
- **结论**：**一致**。v6 没有 levelStartArmor 和 challengeDrawBonus，这两项来自升级系统和洞察弱点挑战（见第 10.4 节）。

### 1.4 回合计数和每回合重置
- **原版**：
  - `battleTurn` 从 1 开始，在**敌方回合最后一步**和玩家灼烧结算一起 +1（`logic/enemyAI.ts:739,789`）。所以「第 t 回合」= 玩家第 t 回合 + 敌方第 t 回合，敌人行动、召唤、塞骰子、叠甲都用这个 t。
  - 敌方回合开始时清零：bloodRerollCount、comboCount、lastPlayHandType（`logic/enemyAI.ts:136`）。
  - 敌方回合结束、回到玩家回合时重置：`armor:0`、`playsLeft:maxPlays`、`freeRerollsLeft`、`hpLostThisTurn:0`、`consecutiveNormalAttacks:0`（`hooks/useBattleCombat.tsx:338-354`）。
  - 抽骰阶段里还会：`setRerollCount(0)`；按收割槽重算 `warriorRageMult`；清空 `tempDrawCountBonus` 和 `relicTempDrawBonus`；加上 levelTurnStartArmor（`logic/drawPhase.ts:135-188`）。
  - **敌人护甲**在敌方回合第一步（灼烧结算）对所有活着的敌人清零（`logic/enemyStatusSettlement.ts:58,60`）。
- **v6**：
  - 敌方回合开始清 bloodRerollCount 和 comboCount（`04_battle.js:548`）。
  - 玩家回合开始清护甲，重置出牌次数、重投次数、本回合损失 HP（`04_battle.js:135`）。
  - 敌人护甲在灼烧循环里清零（`04_battle.js:552`）。
  - `battleTurn++` 放在召唤之后、玩家灼烧之前（`04_battle.js:570`）。
- **结论**：**一致**。v6 每回合还会把 `double_strike` 的额外出牌加进去；原版只有开战第一回合会加被动额外出牌（`logic/battleInit.ts:60` 对比 `useBattleCombat.tsx:347`）。这个遗物本场没有。

### 1.5 原版 Boss 节点的开场流程（演出，供参考）
- **原版**：中 Boss 节点先全屏播放本章终 Boss 的「midBossWarning + dispatch」台词，点击继续。接着依次是 Boss 名横幅、Boss 上场、enter 台词（巫妖 enter 池有 2 句）、`boss_entrance` 特效（`hooks/useBattleLifecycle.ts:83-196`）。
- **v6**：地面裂开升起，加名字横幅和 enter 台词（`04_battle.js:93-108`）。v6 数据里巫妖的 `q.enter` 是原版 `greet` 池的 3 句。
- **结论**：不是规则，只记录在这里。

## 2. 抽骰阶段

### 2.1 上回合的手牌
- **原版**：战士把**所有没打出的骰子**放进弃骰，包括诅咒骰和碎裂骰（`logic/drawPhase.ts:96-108,127-130`）。命运之轮、血之契约这两个遗物的例外本场用不到。
- **v6**：`discard = hand`，然后调 `PILES.discardDice`，碎裂骰会被销毁并删出拥有列表（`04_battle.js:149-150`、`04p_piles.js:20-22`）。
- **结论**：**不一致**，碎裂骰见第 5.9 节。普通骰处理一致。

### 2.2 抽几颗、斩首/完防 +1
- **原版**：
  - `consumeReapSlotsForDraw`：额外抽数 = 斩首槽 + 完防槽，用完清零，槽位上限重置为 1（`logic/warriorReap.ts:71-97`、`logic/drawPhase.ts:153-161`）。
  - 目标手牌数 = min(6, drawCount + 收割加成 + challengeDrawBonus)（`logic/drawPhase.ts:162-163`）。
  - 实际要抽的数 = 目标手牌数 + 各种临时加成 − 保留下来的骰子数；战士保留数为 0（`:189`）。
  - **斩首槽**：一次出牌直接打死任意敌人（AOE 也算）就 +1，DOT 打死不算。每回合上限 1（`logic/warriorReap.ts:18,45-51`、`logic/postPlayEffects.ts:94-151`）。
  - **完防槽**：敌人攻击分支里，伤害 >0、护甲吸收量 == 伤害、HP 没掉、屏障也没吸收，就 +1。上限 1（`logic/warriorReap.ts:58-64`、`logic/enemyAI.ts:552-560`）。
  - 槽位上限只有顺劈斩、霸体铠甲、战神纹章能提高，本场没有。
  - 所以本场每回合最多抽 3+2 = **5 颗**。
- **v6**：斩首在 `04_battle.js:489`（`B.reapKill<1`）；完防在 `04_battle.js:664`（护甲吸收量 === 伤害，且 `reapBlock<1`）；合计 `04_battle.js:163-165`。
- **结论**：**一致**。

### 2.3 过充溢出
- **原版**：rawTargetHandSize 超过 6 时，`warriorRageMult = (raw−6)×0.1`，否则为 0（`logic/drawPhase.ts:164-174`）。结算时用 `ceil(dmg×(1+rageMult))`（`logic/expectedOutcomeCalc.ts:272-274`）。本场 drawCount 3 + 收割最多 2 = 5，**触发不了**。只有洞察弱点挑战的奖励（challengeDrawBonus，最多 +3）叠上去才可能超过 6。
- **v6**：`B.rageMult=(raw-6)*0.1`（`04_battle.js:166`），用法 `03_rules.js:210`。
- **结论**：**一致**。本场没有影响。

### 2.4 骰袋不够时
- **原版**：骰袋数量 < 要抽的数时，把**整个弃骰洗一遍接到骰袋底部**，然后从顶部取（`data/diceBag.ts:30-47`）。抽之前已经先把上回合手牌放进弃骰了（`logic/drawPhase.ts:127-130`，读到的 gameRef 已经刷新）。
- **v6**：`PILES.draw` 同逻辑（`04p_piles.js:17-18`），也是先弃后抽。
- **结论**：**一致**。

## 3. 重投

### 3.1 免费次数与卖血代价
- **原版**：
  - 免费次数 = freeRerollsPerTurn（战士为 1）+ 遗物额外重投 + 回旋骰/连击给的临时次数（`hooks/useReroll.tsx:37-38`、`logic/rerollCalc.ts:24-26`）。
  - 用完之后的第 n 次付费重投（n 从 0 数），代价 = **ceil(maxHp × 2^(n+1) / 100)**（`logic/rerollCalc.ts:30-33`）。maxHp 为 120 时依次是 **3、5、10、20、39、77**。
  - 非战士不能卖血，除非有嗜血骰袋遗物。
- **v6**：`rerollHpCost` 同公式（`03_rules.js:68-73`），没有遗物加成项。
- **结论**：**一致**（本场没有加重投次数的遗物）。

### 3.2 诅咒骰子让代价翻倍
- **原版**：只要选中的骰子里有 isCursed 的，`hpCost *= 2`。免费的时候 0×2 还是 0（`hooks/useReroll.tsx:59-60`）。
- **v6**：`cost>0 && 选中里有诅咒骰` 时 ×2（`04_battle.js:237`）。
- **结论**：**一致**。

### 3.3 生命不足时能不能重投
- **原版**：`hpCost>0 && hp<=hpCost` 时拒绝。也就是 HP 必须**严格大于**代价（`hooks/useReroll.tsx:61-66`）。
- **v6**：`cost >= G.hp` 时拒绝（`04_battle.js:238`）。
- **结论**：**一致**。

### 3.4 血怒
- **原版**：
  - 每次付费重投：bloodRerollCount = min(+1, 5)。如果**重投前已经满 5 层**，这次改成护甲 +5（`hooks/useReroll.tsx:84-92`、`config/balance/player.ts:83-90`）。
  - 结算时伤害 ×(1 + 0.15×min(层数,5))，向上取整（`logic/expectedOutcomeCalc.ts:266-270`）。
  - 敌方回合开始时清零（`logic/enemyAI.ts:136`）。
  - 卖血扣 HP **不计入** hpLostThisTurn，也不触发受伤类遗物（`useReroll.tsx:91`）。
- **v6**：层数、满层给护甲、+15%/层都一样（`04_battle.js:242-245`、`03_rules.js:208-209`）。但 v6 把卖血扣的 HP 计入了 `hpLostThisTurn`（`04_battle.js:241`）。
- **结论**：数值**一致**。hpLostThisTurn 一项**不一致 · 低**，本场只有 masochist 这类遗物会读它，3 个遗物都不读。

### 3.5 重投后骰子去哪、怎么补
- **原版**：
  - 选中的非临时骰子先放进弃骰，然后从骰袋**抽同样数量的新骰子**替换。换上来的可能是另一种骰子；骰袋不够时按第 2.4 节洗回（`hooks/useReroll.tsx:154-172,178-208`）。
  - 重投计数 +1（狂掷风暴遗物例外，`:230-237`）。
  - 每次出牌后，`rerollCount` 被拉到当前上限，**没用掉的免费重投作废**（`hooks/useBattleCombat.tsx:191-198`）。
- **v6**：先放进弃骰再抽，替换的骰子从原位置滚出（`04_battle.js:249-263`），`rerollCount++` 在 `:247`。没有「出牌后作废免费重投」。
- **结论**：换骰规则**一致**。出牌后作废免费重投是**原版有、v6 漏了 · 低**：战士每回合只出 1 次牌，出完就结束回合。

## 4. 出牌结算

### 4.1 牌型判定与倍率
- **原版**：
  - `checkHands`（`utils/handEvaluator.ts:17-131`）的规则：
    - 同牌系（对子、三条、四条、五条、六条）、葫芦系、多对系**互斥**，只取最优的一个。
    - 顺子系（要求点数全不同且连续，长度 ≥3）可以叠加上去。
    - 4+2 和 3+3 都判成大葫芦。
    - 多颗骰子什么都不成时只有「普通攻击」。
  - `ignoreForHandType` 的骰子不参与判定，但颗数 n 用的是全部选中骰子（`:22-23`）。本场的骰子都没有这个属性。
  - 倍率（`data/handTypes.tsx:24-37`）：普攻 1.0、对子 1.8、顺子 1.5、连对 2.4、4顺 2.0、三条 2.8、5顺 2.6、三连对 3.4、6顺 3.5、葫芦 3.8、四条 4.5、大葫芦 5.8、五条 6.5、六条 10。
  - **多牌型叠加**：handMult = 1 + Σ(mult_i − 1) + Σ(牌型等级−1)×0.3（`logic/expectedOutcomeCalc.ts:74-80`）。牌型等级只有事件能升，本场都是 Lv1。
- **v6**：`checkHands` 和倍率表逐行等价（`03_rules.js:3-32`），叠加算法相同（`:118`），没有牌型等级。
- **结论**：**一致**。附带一点：诅咒骰的点数是 0，0-1-2 能组成「顺子」并且打全体，两边一样。

### 4.2 计算顺序与取整（数值上的「四步」）
- **原版**（`logic/expectedOutcomeCalc.ts:56-300`）：
  1. 点数和 X = Σ点数，**baseDamage = ceil(X × handMult)**（`:65,87`）。葫芦或大葫芦让 armorBreak=true（`:99-101`）。
  2. 按获得顺序处理 on_play 遗物，累加 extra 伤害、护甲、回复、倍率、穿透、金币（`:107-171`）。然后加怒火燎原（`:174-178`）。最后每颗骰子的 onPlay 增量各自汇总（`:202-224`）。
  3. **total = ceil(baseDamage × multiplier × (1+等级倍率)) + extra + 等级伤害 + pierce + 等级穿透**（`:241-245`）。multiplier 是遗物和骰子倍率的连乘，**只作用于 baseDamage**，固定伤害不吃倍率。
  4. 依次修正，每一步都 `ceil`：虚弱 ×0.75（玩家有 weak）→ 易伤 ×2（**当前目标**有 vulnerable）→ 血怒 ×(1+0.15n) → 过充 ×(1+rageMult)（`:259-274`）。
  - 护甲 = floor(牌型护甲 + 额外护甲)（`:283`）。
- **v6**：`calcOutcome` 顺序和取整完全一致（`03_rules.js:116-218`：`:119` base、`:126-133` 遗物和怒火、`:197` 骰子、`:204` total、`:206-210` 四个修正）。没有等级加成。
- **结论**：**一致**。

### 4.3 结算演出的四个阶段（原版时序，供演出参考）
- **原版**（`logic/settlement/index.ts:29-32`）：
  - Phase 1：牌型展示 0.6s（`phase1_handDisplay.ts`）。
  - Phase 2：逐颗计分，每颗 0.28s（`phase2_diceScoring.ts:39-48`）。
  - Phase 3：骰子效果 → 遗物（遗物图标刷光）→ 血怒 → 狂暴 → 等级奖励，逐条出现，每条 0.35s，结束时有 0.5s 的 bounce 定格（`phase3_effects.ts:36-185`）。
  - Phase 4：最终伤害飞出。按伤害占敌人最大 HP 的比例分三档顿帧（≥50% 或 ≥60 算重击，≥100% 或 ≥120 算毁灭），时长 0.8 / 1.0 / 1.2s（`phase4_finalDamage.ts:24-56`）。
  - 数值在出牌前就算好了。演出过程**不会改伤害**，分裂骰、磁吸骰、盗贼连击除外。
- **v6**：presentHand 和 launchAttack 是自己的一套演出（`04_battle.js:349-455`），数值同样在出牌前算好。
- **结论**：数值无差别。演出时序原版有定稿参考（另见 `docs\godot-port\08-…`）。

### 4.4 普攻可多选 / 多颗骰子不成牌型时禁用 onPlay
- **原版**：
  - 战士 `normalAttackMultiSelect:true`（`data/classes.ts:74`）。其他职业多选普攻时 UI 拦截（`hooks/useBattleCombat.tsx:96-101`）。
  - 选了多颗骰子、只成「普通攻击」时，`skipOnPlay=true`，**所有骰子的 onPlay 都失效**（`logic/expectedOutcomeCalc.ts:181`、`logic/diceOnPlay/index.ts:43`）。连带血之渴望、泰坦之拳的自伤，碎裂骰的反噬，旋风斩的 +6 也都没有了。
  - 例外一：破甲仍然生效，泰坦之拳的 armorBreak 照样起作用（`expectedOutcomeCalc.ts:189-196`）。
  - 例外二：遗物、怒火燎原、虚弱/易伤/血怒/过充都照常生效。
- **v6**：skip 条件和破甲例外相同（`03_rules.js:134-136,197`），非战士的拦截在 `04_battle.js:230,273`。
- **结论**：**一致**。AOE 例外见第 4.6 节。

### 4.5 葫芦 / 大葫芦的「真伤」
- **原版**：两种葫芦都只是设 `armorBreak=true`，结果是**敌人护甲清零，伤害不被护甲吸收**（`logic/expectedOutcomeCalc.ts:99-101`、`logic/damageApplication.ts:157,246-248`）。不能无视虚弱：虚弱的修正在 total 之后。「无视嘲讽」原版注释写「留作扩展」，没有实现。
- **v6**：`armorBreak=true`，打上「真伤」标签（`03_rules.js:124`）。
- **结论**：**一致**。

### 4.6 AOE 判定
- **原版**：
  - 实际伤害结算：`hasAoe = 有雷元素 || 任一选中骰子 onPlay.aoe || 牌型含顺子/4顺/5顺/6顺`（`logic/damageApplication.ts:89-90`）。**这里不看 skipOnPlay**。
  - AOE 时，**同一个 outcome.damage** 打到每个活着的敌人身上，各自用自己的护甲吸收（armorBreak 时全部清零）。状态效果也挂给所有敌人（`:150-205`）。
  - 虚弱、易伤、斩杀线**只按当前目标**计算。
  - 预览用的 `detectAoeActive` **会**排除多选普攻（`logic/aoeDetection.ts:24-27`），所以「多选普攻里带旋风斩」这种情况，原版预览显示单体，实际打全体。
- **v6**：`out.aoe = !skip && (雷 || aoe) || 顺子类`（`03_rules.js:215`），每个目标调一次 `hitEnemy`（`04_battle.js:427-443`）。
- **结论**：一般情况**一致**。多选普攻带旋风斩时**不一致**：原版结算打全体，v6 不打。原版自己的预览和结算也矛盾，以哪个为准需要拍板。

### 4.7 出牌次数和自动结束回合
- **原版**：maxPlays 1。出牌时 `playsLeft-1`、`comboCount+1`（`hooks/useBattleCombat.tsx:175-185`）。`playsLeft<=0` 或手里没有可用骰子时，**1 秒后自动结束回合**（`:389-451`）。也可以一张牌不出直接结束回合。
- **v6**：`playsLeft-1`（`04_battle.js:278`），出完或没骰子时等 0.9 秒再 `doEndTurn`（`:324`）。
- **结论**：**一致**。

### 4.8 作用到玩家身上的部分（护甲、回复、自伤）
- **原版**：出牌结算后，`armor += outcome.armor`；heal<0 时 `hp = max(1, hp+heal)`，**自伤不会致死**；否则 `hp = min(maxHp, hp+heal)`（`logic/damageApplication.ts:497-503`）。回复和自伤先在 heal 里合并成净值再应用。
- **v6**：同样合并成净值，`changeHp` 里自伤保底 1（`04_battle.js:283-284,327-332`）。
- **结论**：**一致**。

  1. **召唤检查**，回合开始时做（`:141-173`）。
  2. 玩家中毒结算（`:175-221`）。
  3. 敌人灼烧结算，**同时所有敌人护甲清零**（`:223-242`、`enemyStatusSettlement.ts:47-64`）。
  4. 敌人中毒结算，所有敌人的状态持续回合 −1（`:244-263`、`enemyStatusSettlement.ts:74-94`）。
  5. 每个敌人依次行动（`:265-701`）。
  6. 精英/Boss 塞垃圾骰（`:704-715`）。
  7. 精英/Boss 叠护甲（`:717-728`）。
  8. `battleTurn+1`，玩家灼烧结算，玩家状态持续回合 −1（`:730-790`）。
  - 步骤 5–7 用的都是**回合开始时的敌人快照**（`:266`）。所以：新召唤的敌人当回合**不行动**；被 DOT 打死的敌人仍然会行动；阶段按 DOT 之前的血量选。`:141` 的注释说想让新召唤的当回合就行动，代码没有做到。
- **v6**（`04_battle.js:547-576`）：
  - 清零 → 玩家中毒 → 灼烧和护甲清零 → 死亡判定 → 中毒和状态递减 → 死亡判定 → 行动（实时 `alive()`）→ **按敌人逐个**做塞骰、叠甲、**召唤** → `battleTurn++` → 玩家灼烧 → 玩家状态递减。
- **结论**：大体**一致**。**召唤时机不同**：原版在回合开始，v6 在回合末尾；新召唤的敌人当回合都不行动，实际效果相同。快照缺陷 v6 没有照搬，本场玩家没有 DOT 手段，影响低。

### 8.2 行动选择（阶段和循环）
- **原版**：
  - 阶段：从前往后找**第一个满足 hp ≥ maxHp×hpThreshold 的阶段**。没有阈值的阶段作为兜底，选最后一个（`data/enemies.ts:21-37`）。
  - 动作 = `actions[((t−1) % len + len) % len]`，t 是 battleTurn，**所有敌人共用这一个计数**（`:42-43`），召唤物也不例外。
  - 数值 = scalable===false 时取 baseValue，否则 floor(baseValue×dmgScale)（`:44-50`）。**返回值里不带 curseDice 和 curseDiceCount**。
  - 巫妖：hp ≥ 86.4（216×0.4）时用第一阶段，低于时用第二阶段（`config/enemyEliteBoss.ts:341-356`）。
- **v6**：`enemyAction` 同公式，但多返回了 curseDice（`03_rules.js:230-236`）。
- **结论**：选择规则**一致**。多出来的 curseDice 导致了第 8.4 节的差异。

### 8.3 caster 的「攻击」动作
- **原版**：
  - caster 和 priest 的「攻击」**一律转成技能**（`logic/enemyAI.ts:304-309`）。
  - 巫妖的「亡灵风暴」「骸骨之矛」，以及第二阶段没有描述的「攻击 8」，都不在 DOT 或控制字典里，于是走 `executeCasterSkill`（`:431-471`）。
  - 这个函数里巫妖没有原型（archetype），走默认概率，用的是 **e.attackDmg（10）**，动作本身的数值（16/14/8）**完全不用**（`logic/enemySkills.ts:207-265`、`config/balance/enemy.ts:57-78`）：
    - 40%：中毒 max(2, floor(10×0.4)) = **4**
    - 30%：灼烧 max(1, floor(10×0.3)) = **3**（持续 3 回合，但实际只结算一次，见第 9.1 节）
    - 30%：中毒 max(1, floor(10×0.25)) = **2**，外加**虚弱 1 层、持续 2 回合**
  - DOT 放大（dotAmplifier）对 `boss_` 开头的敌人不生效，倍率恒为 1（`logic/enemyTraits.ts:26-29,134-143`）。
  - **巫妖永远不会直接攻击玩家。**
- **v6**：同样转技能并调 `casterSkill`，概率和数值完全一样（`04_battle.js:586-587,601,640-645`）。
- **结论**：**一致**。

### 8.4 「技能」动作施加的东西
- **原版**：
  - 描述字典（`logic/enemyActionDispatch.ts:23-39`）：灼烧 → burn，剧毒 / 火球 / **诅咒** / 诅咒爆发 → poison，虚弱 → weak，易伤 → vulnerable。
  - caster 命中字典时：
    - DOT 数值 = action.value（乘 DOT 放大倍率，巫妖恒为 1）。灼烧带持续 3 回合（`logic/enemyAI.ts:381-402`）。
    - 控制状态 = 1 层，持续 2 回合（冻结为 1 回合；priest 另加圣怒层）（`:403-413`）。
  - 巫妖第一阶段：**灼烧 2 层**；**诅咒 → 中毒 1 层**。
  - 巫妖第二阶段：**虚弱 1 层、2 回合**；**易伤 1 层、2 回合**。
  - 叠加方式：同类型时层数相加，持续回合取较大值（`enemyActionDispatch.ts:72-87`）。
- **v6**：
  - 灼烧、虚弱、易伤的数值和持续回合一样（`04_battle.js:597-600`）。
  - **「诅咒」**：v6 先检查 `a.curseDice`，命中就往骰袋塞诅咒骰，然后 return（`04_battle.js:595`）。它的 DOT 字典里也没有「诅咒」（`03_rules.js:237`）。
- **结论**：灼烧、虚弱、易伤**一致**。**诅咒不一致**，原版是中毒 1 层（汇总表第 1 条）。

### 8.5 防御、近战逼近、攻击值修正
- **防御**：
  - 原版：护甲 += floor(action.value × 原型系数)，只有 bulwark 型是 2 倍。巫妖是 **+15**（`logic/enemyAI.ts:323-345`）。
  - v6：同（`04_battle.js:588-591`）。
  - 结论：**一致**。
- **逼近**：
  - 原版：近战（warrior/guardian）距离 >0 时，这一回合只把距离 −1，不做别的（`logic/enemyAI.ts:280-291`）。召唤出来的食尸鬼距离是 **2**（`data/enemies.ts:75`）。
  - v6：规则相同（`04_battle.js:585`），但召唤物距离设成 1（`:568`）。
  - 结论：规则**一致**，初始距离**不一致**。
- **攻击值**：
  - 原版（`logic/attackCalc.ts:45-87`），按顺序：
    1. 基础值：动作是「攻击」时取 action.value，否则取 attackDmg（`enemyAI.ts:495,507`）。
    2. warrior 类型 floor(×1.3)。
    3. 乘以**特性和原型倍率**再 floor（`enemyTraits.ts:91-131`）。berserker 有：血怒 ×(1+0.4×层)，最多 4 层，**被出牌打中没死 +1**（`damageApplication.ts:195-205,374-381`）；复仇 ×(1+0.5×层)，**每有一个敌人被出牌打死 +1**（`enemyTraits.ts:177-187`）。
    4. 加力量。
    5. 敌人虚弱 floor(×0.75)，最少 1。
    6. 玩家易伤 floor(×2)。
    7. 法术反噬。
  - v6 `attackValue`（`03_rules.js:258-267`）：×1.3、力量、虚弱、易伤都有，**没有第 3 步的特性倍率**。
  - 结论：×1.3 等**一致**。berserker 的血怒和复仇是**原版有、v6 漏了**（汇总表第 3 条）。
- **武力系的「技能」**：
  - 原版：warrior、ranger、guardian 碰到 DOT 或控制类技能时，改成「普攻 + 附带效果」。普攻用 attackDmg；附带的控制是 1 层、2 回合；附带的 DOT 是 max(1, floor(value/2))（`enemyAI.ts:360-375,658-689`）。食尸鬼的「虚弱」就是 13 伤害 + 虚弱 2 回合。
  - v6：同（`04_battle.js:596,603-610`）。
  - 结论：**一致**。

### 8.6 召唤
- **原版**（`logic/enemySummonRevive.ts:38-78`）：
  - 条件：battleTurn ≥1、(t−offset) % interval == 0、已召唤数 < maxTotal、当前存活数 < waveCap、HP 低于 hpThreshold（如果配置了）。巫妖的配置是 interval 3、count 1、maxTotal 4、waveCap 4（`config/enemyEliteBoss.ts:340`）。所以**第 3、6、9、12 回合各召唤 1 只**，场上最多 4 个敌人（巫妖 + 3 只食尸鬼），总共最多召 4 只。
  - 召唤物用 `buildEnemy(minionCfg, 1, 1)`，**不缩放**：28 HP，attackDmg 10，距离 2，标记 isSummoned（召唤物不能再召唤）。
  - 时间线：第 3 回合开始时召出来 → 当回合不行动 → 第 4、5 回合逼近 → **第 6 回合第一次攻击**。第 6 回合的动作序号是 (6−1)%3 = 2，也就是「虚弱」技能，变成 13 伤害 + 虚弱。之后是攻击 13、撕咬 15，循环。
- **v6**：
  - 在回合末按 `t % interval === offset` 判断，条件基本相同。
  - 属性用 `buildEnemy(mc, hpScale×0.6, dmgScale×0.7)`，距离 1（`04_battle.js:567-568`）。depth 7 时：30 HP，attackDmg 7，动作 7/8 → 实际攻击 9 / 10 / 9。第 5 回合第一次攻击。
- **结论**：召唤的回合、数量、上限**一致**。属性、距离、首攻回合**不一致**（汇总表第 2 条）。

### 8.7 Boss 特性：叠护甲和塞垃圾骰子
- **原版**：
  - 判定方式按最大 HP：`isElite` 要求 >80 且 ≤200，`isBoss` 要求 >200（`logic/elites.ts:19-26`、`config/balance/enemy.ts:97-101`）。depth 7 的巫妖（216）走 Boss 规则；食尸鬼（28）两种都不是。

- **v6**：
  - 叠护甲同公式（`04_battle.js:566`）。
  - 塞骰的两个 if **互相独立**（`:566`）。第 6、12… 回合如果 HP<40%，会同时塞诅咒和碎裂。也是放到骰袋底部（`04p_piles.js:27`）。

- **结论**：叠护甲**一致**。塞垃圾骰**不一致**（汇总表第 4 条）。判定方式不同，但在 depth 7 时结果一样（汇总表第 17 条）。

## 9. 状态

### 9.1 灼烧 burn
- **原版**：
  - 玩家身上：**敌方回合最后一步**一次性造成「层数」点伤害，**无视护甲**（奥术屏障可以挡），然后整个状态移除。持续回合数不起作用（`logic/enemyAI.ts:747-764`）。巫妖在敌方回合里施加的灼烧，**同一个敌方回合末尾就结算掉**。
  - 敌人身上：敌方回合第一步结算，然后移除（`enemyStatusSettlement.ts:47-64`）。本场玩家没有能上灼烧的手段。
- **v6**：玩家灼烧在 `04_battle.js:571-572`（DOT 绕过护甲，`:651`），敌人灼烧在 `:552`。
- **结论**：**一致**。

### 9.2 中毒 poison（巫妖**会**上毒，不能简略带过）
- **原版**：
  - 玩家身上：**敌方回合开始时**（召唤之后）造成「层数」点伤害，**无视护甲**，然后层数 −1，降到 0 移除（`logic/enemyAI.ts:179-217`）。
  - 叠加：层数相加。
  - 本场的来源：随机施法（4 层，或 2 层 + 虚弱），「诅咒」动作（1 层）。4 层中毒总共造成 4+3+2+1 = 10 点伤害。
- **v6**：`04_battle.js:549-550`。
- **结论**：结算方式**一致**。来源不一致见第 8.4 节。

### 9.3 虚弱 weak / 易伤 vulnerable
- **原版**：
  - 玩家虚弱：玩家造成的伤害 ceil(×0.75)。玩家易伤：**敌人攻击**伤害 floor(×2)，DOT 不受影响（`expectedOutcomeCalc.ts:260-261`、`attackCalc.ts:78-80`、`config/balance/player.ts:116-121`）。`attackCalc.ts` 的注释写易伤 ×1.5，实际常量是 2.0。
  - 敌人虚弱：攻击 floor(×0.75)，最少 1。敌人易伤：玩家对它的伤害 ceil(×2)，只看当前目标。
  - 持续回合在**敌方回合末**和玩家灼烧一起 −1。用的是 `enemySkills.tickStatuses`：中毒和灼烧不处理；有持续回合的减回合；没有持续回合的减层数（`enemySkills.ts:24-36`）。
  - 所以敌方第 N 回合施加的 2 回合状态：到第 N 回合末剩 1，**在玩家第 N+1 回合和敌方第 N+1 回合都有效**，第 N+1 回合末移除。
  - 同一个敌方回合里，巫妖先施加了易伤，后面行动的食尸鬼当场就打 ×2：伤害是读实时玩家状态算的（`enemyAI.ts:508`）。
- **v6**：
  - 修正系数相同（`03_rules.js:206-207,263-264`）。
  - `tickStatuses` 只处理持续回合，没有持续回合的状态永远保留（`03_rules.js:61`）。本场的虚弱和易伤都带持续回合，结果一样。
  - 也是在敌方回合末递减（`04_battle.js:573`）。
- **结论**：**一致**。没有持续回合的状态处理方式不同，本场遇不到。

### 9.4 玩家受伤与护甲
- **原版**：
  - `absorbPlayerDamage`：先用奥术屏障，再用护甲（DOT 跳过护甲），剩下的扣 HP（`logic/battleHelpers.ts:62-99`）。
  - 玩家护甲在**玩家回合开始时清零**（`useBattleCombat.tsx:345`），所以出牌拿到的护甲能挡住紧接着的敌方回合。
- **v6**：`playerTakeHit`（`04_battle.js:647-672`），护甲在 `:135` 清零。
- **结论**：**一致**。

## 10. 胜利

### 10.1 垃圾骰子清理
- **原版**：胜利时，把拥有列表、骰袋、弃骰里**所有的** cursed 和 cracked 全部删掉（`hooks/useBattleVictory.ts:66-69`）。手牌没处理，但拥有列表里已经没有了，下一场会用拥有列表重建骰袋。
- **v6**：先把手牌放进弃骰（碎裂骰保留），再执行 `victoryCleanup`（`04_battle.js:677-678`、`04p_piles.js:36`）。
- **结论**：**一致**。

### 10.2 奖励
- **原版**：
  - 中 Boss 不算最终 Boss，走 `diceReward → loot → map`（`logic/lootHandler.ts:107-125`）。
  - **骰子三选一**（`components/DiceRewardScreen.tsx:33-66`、`data/dice.ts:211-235`）：
    - 奖励池：战士骰按稀有度给权重（普通 1、罕见 2、稀有 3、传说 3），外加 blade、amplify、split、magnet、joker、chaos 各 1 份。
    - 已拥有的特殊骰权重 ×3。
    - 刷新价格：第一次免费，之后 5、10、20…（`config/balance/player.ts:56-63`）。
  - **金币** = Σ dropGold（60 + 20×食尸鬼数）+ on_battle_end 遗物（`lootHandler.ts:32`）。
  - **遗物**：掉落的战斗类型判定是 `名字含 'Boss' ? boss : 有 rerollReward ? elite : enemy`，enemy 类型的掉落率是 0（`lootHandler.ts:78-90`）。巫妖叫「枯骨巫妖」，也没有 rerollReward，所以**不掉遗物**。中 Boss 也不给精英额外奖励（`:43-54`）。同章的根须巨像有 `rerollReward:3`，会按精英池掉 1 个遗物。这里看起来像原版缺陷，但代码就是这样运行的。
  - 完成洞察弱点挑战时，额外给一个挑战宝箱（`:73-76`）。
- **v6**：
  - 金币加上。
  - 遗物三选一，从传说/稀有里抽（`05_meta.js:164`）。
  - 骰子三选一，**Boss 池只放稀有和传说**，通用骰只有 3 种，没有「已拥有 ×3」（`03_rules.js:330-336`），刷新价格相同（`05_meta.js:166-169`）。
- **结论**：**不一致**（汇总表第 7 条）。阶段 1 文档要求「胜利后选一个遗物奖励」，和原版代码不一致，需要拍板。

### 10.3 残血台词与转阶段
- **原版**：
  - 残血台词：只在**单体**伤害路径里，伤害后 hp/maxHp < 阈值（`configId` 以 `boss_` 开头的是 0.5，其他 0.3）时，每个敌人说一次 lowHp 池里的话（`logic/damageApplication.ts:291-358`）。AOE 路径不说残血台词，反而每次被打中都会说一句死亡台词（`:186-192`），看起来是缺陷。
  - **转阶段**：伤害前 ≥ 阈值、伤害后 < 阈值时，触发阶段横幅、`boss_entrance` 特效和台词。台词优先从 `phase2_taunt` 池取，巫妖没有这个池，所以用 lowHp 池（`logic/bossPhaseSwitch.ts:38-85`、`damageApplication.ts:301-334`）。巫妖的阈值是 0.4。同一下伤害既触发转阶段又低于 50% 时，这一下不再单独说残血台词。
- **v6**：`hitEnemy` 里所有伤害路径都用 Boss 0.5、普通 0.3 的阈值说 lowHp 台词（`04_battle.js:471`），没有转阶段事件。
- **结论**：50%/30% 残血台词**一致**。40% 转阶段演出是**原版有、v6 漏了**（汇总表第 9 条）。阶段 1 文档里的「残血转阶段（lowHp 台词 + 演出升级）」在原版对应的就是这个 40% 事件。
