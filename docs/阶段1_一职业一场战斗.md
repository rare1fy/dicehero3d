# 阶段 1：一个职业、一场战斗（正式工程的第一个可玩切片）

先读 `CLAUDE.md`，里面有定稿表、历史问题清单和工作铁律，这些都是本任务的约束。

## 目标
在正式工程里做出**一个职业打完一场完整战斗**的切片，让用户评估 3D 化以后的整体表现力，再决定怎么往下推进。重点是表现力拉满，不是内容多。

- **职业：** 嗜血狂战（warrior）。
  - 带初始 6 颗骰子，另外再给 3–4 颗最有代表性的狂战职业骰子（从 `w_*` 里挑表现差异最大的几颗）。
  - 开局带 3 个遗物，保证战斗里都会触发，用来展示遗物的飞行演出。
- **战斗：** 对阵 Boss 枯骨巫妖（`boss_lich_forest`），数值、行动、台词都用 `01_data.js` 里的原数据。
  - 必须包含：Boss 登场演出、残血转阶段（lowHp 台词 + 演出升级）、玩家多回合出牌、敌方回合、状态效果（灼烧、诅咒、虚弱、易伤）、击杀慢动作和死亡演出、胜利。
- **进出场：**
  - 进场：开场先给一个章节全景，镜头要比 v6 第 2 轮更高、更全览，然后无缝俯冲进战场。
  - 出场：胜利后选一个遗物奖励，演出用 v5 的遗物做法；然后镜头拉回全景。
  - 地图只做这一小段，不做完整章节。
- **语音：** Boss 语音如果 `GameProtos\voice\out_roles_v1` 里已经有成品就接上；没有的话先留好接口，用字幕气泡代替。

## 做法和顺序

1. **对齐参考（必须先做，做完给用户确认）**
   - 打开 v5（`_ref\px3d\demos\dicehero3d.html`）和 v6 第 2 轮（`demos\dicehero6.html`）的构建。
   - 截图并录几秒短片，至少录这几样：
     - v5 的骰子：外形、投掷、选中、出牌特效、重投。
     - v5 的遗物：漂浮的小模型、触发时发光拖尾飞到武器。
     - v6 第 2 轮：施法、攻击、受击反馈。
     - v6 第 2 轮：全景地图和俯冲切入战斗。
   - 把素材整理成一页「参考对照」，放在 `docs\refs\`；同时写一页迁移计划，列出哪个模块从哪个版本的哪些文件迁过来，哪些要重做。
   - 一起给用户看，请用户确认「上版的骰子和遗物」指的就是这些。**确认之后再写代码。**
2. **搭工程**
   - Vite + TypeScript + three.js / cannon-es，从 npm 打包，不用 CDN；初始化 git。
   - 接入 pxui 的运行时和 platform 层。
   - 能出浏览器单文件构建，也要验证小游戏构建能编译通过（开发者工具里的真机验证等用户开了服务端口再做）。
3. **迁规则层**
   - 原版 TS 逻辑加上 3D 版的修复，做成纯函数，不碰 three 和 DOM。
   - 写单测，把 `piles_test.mjs` 的用例迁过来；机器人能自动打完这场战斗，零报错。
4. **迁定稿模块：** 骰子的交互和演出（v5）、遗物演出（v5）、战斗反馈（v6 第 2 轮）、结算文字、状态特效。只迁移机制、手感和演出节奏，不改设计；视觉外观做成可以替换的。
5. **画面方向探索（自由发挥，不参考之前的 demo）**
   - 在同一场战斗上做 3 个左右差异明显的画面方向，做成可切换的外观包（如 `?look=A/B/C`）。每个方向都要覆盖完整的一套：渲染和光影、狂战英雄和枯骨巫妖的造型、Boss 战场景、骰子材质、特效、UI 视觉。
   - 给用户看时，每个方向用同一时刻、同一镜头的截图和短片并排对比，各附一句话说明思路。
   - 用户挑一个（或混搭）后，再按定稿表「角色」「场景」两行的功能要求细化。
6. **镜头导演、演出队列、音频**
   - 按定稿表和表现力清单把表现往 3A 方向推。
   - 每加一项强化都放在开关后面，方便对比。
7. **自测，然后给用户看**
   - 三个尺寸截图，关键时刻录短片；逐条核对历史问题清单；检查性能预算（draw call、帧率）和包体。
   - 发布成私有 artifact，以后都更新同一个链接。
   - 在 `CLAUDE.md` 的展示记录里登记一行，打 tag。
   - 跟用户汇报：做了什么、哪些开关可以对比、自己觉得还弱的地方。

## 这一阶段不做
- 法师、盗贼。
- 其他敌人。
- 完整章节地图。
- 商店、营火、事件。
- 设置界面。
