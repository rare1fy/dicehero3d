# 战斗界面 UX v3（用户在 Figma 稿上逐条拍板，13:00～14:00）

Figma：https://www.figma.com/design/dvBiHsxXoIkbNA9bnolRUX （你打不开也没关系，下面是全部要点）。坐标以 1280×720 为参考，手机横屏同比例。**这一份取代 SHOW3 / SHOW4 里所有关于布局位置的说法**（行为、动画、状态的要求仍然有效）。

## 1. 屏幕分区
- **左手（左下）= 骰子从哪来**：
  - 重投石钮（八角，约 104px，中心约 125,617）。**按钮上沿一排小灯 = 本回合还能重投几次**，用掉一次熄一盏；选中骰子时整个按钮亮金光，**选中几颗就有几颗小骰子绕着按钮转**（第四轮已实现、用户点名保留），场上被选中的骰子头顶冒一个小重投箭头（= 点重投就重投它们）；狂战卖血时环绕的小骰子变红；次数用完灯全灭、按钮变暗；狂战免费次数用完后按钮变血红，灯位换成一滴血 + 代价数字。按钮上不要放其他静态小方块（静态的会被看成次数）。
  - **准备区没有底座、不排格子**：挣来的骰子**悬浮**在重投按钮右上方（约 x 200～360、y 550～660），高低和角度不规则，轻轻上下浮动，下面淡投影，周围飘能量粒子。挣到时在这里凝出，回合开始从这里扔进场景。
- **中间（底部正中）**：
  - **血瓶在屏幕正中**（约 x 584～696、y 574～694）。回合末会扣血的中毒 / 灼烧，在液面上先画出将要扣掉的那一截（较暗的一段）。
  - **血瓶左边 = 正面状态面板**：暖色石台、金边、圆角；图标圆形金边，角标 = 层数 / 回合数（护甲、狂暴、屏障…）。
  - **血瓶右边 = 负面状态面板**：暗红石板、红边、缺角带裂纹；图标方形红边 + 裂角（中毒、虚弱、灼烧…）。
  - 两块面板视觉上一眼能分开。超过 3 个时面板向外加宽，再多折叠成「+N」。点图标看 tips。
- **右手（右下）= 技能栏**（用户 15:20 在 Figma 1.1 / 1.2 上亲手调的）：4 个技能槽在右下**排成一横排**（散骰、同点、连环、阵列，约 x 923～1214、y 584，原尺寸 72×100，间距约 73）。**不是弧形轮盘。**
- **结束回合按钮**：三个职业都有，在右侧（位置见 §1b）。魔导的这个按钮就是「吟唱」，带吟唱环光效；狂战、刺客是同一个石钮的「结束回合」样式。没有骰子或没有合法出手时仍自动结束（用户：「其他职业也应该有结束回合按钮才对」）。
- 左上：钱袋 + 遗物槽。顶部正中：首领血条（只在首领战）。

## 1b. 手机握持（用户：「按钮太靠边，手机握持很难操作」「骰子在中间大拇指不好选，挨太近也不好选」）——**本节的位置和尺寸覆盖上面第 1 节和 Figma 里的坐标**
参考仍是 1280×720（横屏，高度 720 对齐；iPhone 横屏 1 参考像素 ≈ 0.54pt）。双手横握时拇指根压住屏幕外侧约 15mm，拇指尖舒服的落点在离左右边 12%～25% 宽度、离底边 15%～30% 高度的两块扇形里；正中偏上最难够。
- **安全区与锚定**（用户：「两边空出来太多了」）：所有 HUD 先扣掉 `env(safe-area-inset-*)`，再**贴着安全区的左右边缘锚定**：左手组（重投、悬浮区）锚左下，右手组（技能栏、出牌按钮、结束回合）锚右下，血瓶和状态面板锚底部正中。不要在屏幕中间取一块 16:9 再往里排（那样宽屏两侧会空出一大片）；离边距离按下面的数字固定，屏幕越宽，左右两组离得越远。
- **边距**：任何可点元件的外沿，离安全区左右边 ≥ 64、离底边 ≥ 32。
- **拇指位**：重投按钮中心约（安全区左边 + 200，y 560）；激活后的出牌按钮中心约（安全区右边 − 200，y 548）；魔导吟唱按钮离右边 ≥ 64、y 约 400（不放垂直正中，往下挪进拇指扇形）。
- **点按尺寸**：主按钮（重投、出牌按钮、待机技能槽）可见尺寸 ≥ 96；任何能点的东西（缩小的技能槽、遗物、状态图标、敌人牌）点击热区 ≥ 88，外观可以小，热区要补足。待机技能槽 84×112、间距 10；缩小槽外观 ≥ 56×74。横向放不下时，状态面板先折叠成「+N」，不要压缩按钮。
- **左侧玩家区**（用户：「血瓶在中间感觉好孤独，有点小奇怪」，覆盖下面「中间（底部正中）」那一条）：血瓶不再单独放在底部正中，而是放在英雄正下方附近、重投按钮右侧，正负状态贴在血瓶两侧，三者底下一条共同的台沿连起来，读成一组「我的骰子 + 我的血 + 我的状态」。右侧是技能栏和结束回合；底部中间留空，上面是骰场。
- **三条横带（屏幕空间，从上到下）**——角色、骰子、HUD 各占一条，互不侵占（用户：「怎么保证骰子在场景中落下但是不影响场景中角色站位」）：
  - **舞台带**（屏幕高度约 14%～58%）：英雄和所有敌人连同头顶敌人牌都在这里。站位**横向排开**：英雄在左（屏幕 x 约 28%～36%），敌人在中右（约 50%～78%），不贴屏幕边缘。近战冲锋、法术弹道都在这条带里横着走，不往镜头方向冲。
  - **骰场带**（约 60%～73%）：骰子只落在这里。它是英雄和敌人脚下前方、离镜头更近的一条地面（场地里画一块浅色石台或符文圈，叫「骰场」，让它看起来是专门放骰子的地方）。因为离镜头更近，骰子在屏幕上永远在角色下方：不会挡住角色身体，角色也不会站在骰子上。
  - **HUD 带**（约 75% 以下）：按钮、血瓶、状态。
- **骰场的做法**：骰场是世界里固定的一块地面区域（不是每次从屏幕坐标反算到地面），里面预先排好 6 个落点槽，排成一条中间略低的微笑弧，槽间距保证屏幕上中心距 ≥ 120、骰子屏幕尺寸 ≥ 72。骰子从左下悬浮区扔出，带弹跳滚进分配好的槽，所以不会互相叠、也不会落到别处。魔导的留场骰占着自己的槽，新骰补进空槽。
- **镜头取景（和「按敌人大小取景」合并）**：每次重新取景时解一个约束：舞台带装下所有角色（头顶敌人牌到脚），骰场映射到骰场带，HUD 带只有地面。大型敌人让镜头拉高拉远时，骰子按镜头距离整体放大，屏幕尺寸仍 ≥ 72。只在入场、召唤或新一波、大型敌人死亡时重新取景，选骰、瞄准、骰子在场上时镜头不动。
- **选骰热区**：点击按屏幕距离选最近的骰子（半径 60 内），不要只靠网格射线命中；骰子之间的空隙点下去也要选中最近那颗。

## 2. 技能槽长什么样
- 槽中间是**技能图标**（魔导：奥术弹 紫色法球、冰锥 冰晶、闪电链 闪电、陨石 火球；狂战、刺客同理各自画）。
- 槽下沿压一枚**小徽章**画对应的牌型（散骰 / 同点 / 连环 / 阵列）——牌型是辅助图形，不是主体。
- 槽下面是**不超过 4 个字的效果标签**，按类别着色（控制 青、爆发 橙、弹射 黄、补骰 绿、防御 钢灰、单体 米白）：
  - 魔导：奥术弹 单体 / 冰锥 控制 / 闪电链 弹射 / 陨石 爆发
  - 狂战：劈砍 单体 / 顺劈斩 横扫 / 盾墙 防御 / 狂血 吸血
  - 刺客：袖箭 补骰 / 背刺 处决 / 影步 补骰 / 毒雾 群毒
- 技能全名和各档效果在 tips 和放大的技能卡上。

## 2b. 技能图标和底板分层（用户 15:50：「技能图标和按钮底板要独立出来，才能做出立体的酷炫效果」）
- 每个技能槽 / 出牌按钮由三层组成：**底板层**（八角石面 + 厚度 + 能量环 + 质变光芒 + 落在石面上的图标投影）、**悬浮层**（技能图标单独一个 3D 体素模型，抬离底板，有自己的投影）、**前景层**（档位灯、数值胶囊、牌型徽章、附加效果、目标头像）。
- 图标抬起高度随状态变：暗 4 / 可用 7 / 激活 1 档 12 / 2 档 16 / 3 档 22（像素，1280×720 参考），激活时图标同时放大（1.06 / 1.12 / 1.2），3 档略微倾斜；图标顶部可以超出底板边缘。
- 两层独立动画：图标待机轻微上下浮动（±2，约 2 秒一周）并缓慢自转小角度；可用时抬高一点；激活时图标先弹起再落到悬浮高度并原地转一圈（约 0.3 秒）；升档时图标再抬高、放大，3 档换成升级版图标；拖拽瞄准时底板不动、图标朝目标方向倾斜；出手时图标沿箭头方向飞出化成光。投影随图标高度变淡变小。
- 实现上：图标是独立的体素网格（挤出的像素图标），底板是另一个网格；UI 层透视（第 5 节）对两层分别生效，才能看出前后错位的立体感。

## 3. 技能激活 = 技能槽「长成」出牌按钮（用户 15:00 定，取代之前的「石台 + 大卡」）
- 不要方形大卡片、不要焦点石台。**被激活的技能槽本身滑到技能栏最右端（拇指位置，约 x 1062～1198、y 540），平滑放大成出牌按钮**（约 0.2 秒，带回弹）；其余 3 个槽缩小到约 45×62、变暗，在按钮左边排成一排（约 x 900 / 954 / 1008、y 608）。
- 放大不是整体等比放大，而是**重新排版**：技能图标放大；槽下的效果标签淡出，换成预计数值胶囊（例：18）；上沿亮出档位灯（3 颗，亮几颗 = 第几档）；**牌型小徽章留在边沿、不放大**；外圈一圈能量环。石面金边发光。
- **档位要用形态表现，不靠文字**（用户 15:40：「同样的牌型，档位不同状态也应该不同，现在文字表现太弱」）。同一个按钮随档位变：
  - 1 档：基础形态，金边；左下 1 个敌人头像 = 打 1 个目标；上沿亮 1 颗灯。
  - 2 档：边框转亮橙金、多一圈外环、图标发光；右侧挂上新增效果的图标（例：冰锥 → 冻结）；亮 2 颗灯。
  - 3 档（质变，一般 4 颗起）：外形变化——八角后长出一圈尖角光芒，白青色；图标换成升级版（例：冰锥 → 冰环）；左下变成一群敌人头像 = 打全体；3 颗灯全亮。
  - 每个技能各档的「附加效果图标」「目标数」「升级版图标」由技能数据给出（新增字段），表现层按档位组装。
  - 升档反馈：选骰时每加一颗、档位上升，按钮原地弹一下（1.0 → 1.12 → 1.0，0.15 秒），新灯「叮」一声、外环闪一下；到质变档额外一圈冲击波 + 外形长出光芒 + 图标替换 + 更重的音效。减少骰子时反向降档，不播冲击波。
  - 去掉「2颗 1档」这类文字。
- 一次选骰一般只激活一种牌型。少数同时成立的情况（狂战多散骰 + 同点），两个都长成按钮，但**按数量缩到中号（约 0.8 倍）**，并排占技能栏最右端，其余两个缩小排在左边，各自能点能拖。
- 凑不成牌型：技能栏同样收成小号（4 个都缩小变暗，排在左边），**拇指位置换成灰色虚线圆盘 + 选中骰子的缩影**；此时重投按钮亮起。
- **瞄准箭头照炉石传说的做法**（用户：「箭头短的时候中间的虚线挤一起了，不是固定的间距」）：沿曲线按弧长**等距**摆一节节指向目标的 V 形人字，节的大小和间距固定，拖得越远节越多；所有节以固定速度从按钮流向手指；箭头头部单独一块，朝向终点切线，悬停敌人时吸附到敌人胸口；弧度随距离变，近平远弯。
- 出手：点按钮 = 打当前目标；按住往外拖 = 瞄准：**按钮原地不动**（略微下压 + 外圈瞄准光环），只有体素弧形箭头从按钮伸向手指，悬停的敌人高亮 + 预计伤害；松手在敌人上 = 出手（按钮化成光，接「技能与点数」演出）；松手在空处或回到按钮上 = 取消，箭头收回。
- 取消选择：按钮缩回原槽，其余槽回到一横排原位。
## 4. 状态在角色身上
- 英雄头顶：职业状态（魔导吟唱环 3 格 / 狂战 5 个血滴 / 刺客两把匕首），身上持续能量随层数变盛。
- 正负面状态：身上有表现（中毒冒绿泡、灼烧冒火、冻结冰壳、眩晕转星、虚弱发灰、易伤红裂纹），精确数字在血瓶左右两块面板（英雄）/ 血条下方一行（敌人）。
- 敌人牌：意图图标 + 血条 + 状态行；当前目标脚下红圈；冻结的敌人意图变灰加冰框。

## 5. 3D UI 透视
UI 层小视角透视相机，元件按屏幕位置朝屏幕中心转 15～25°（左下的往右上转），露出侧面和厚度，轻微待机摆动。

## 5b. 按钮要有体积（用户：「按钮是不是 3D 的？明显体积感不够，显得太薄了」）
- 按钮和技能槽、重投、结束回合、血瓶都是 UI 层里的 3D 体素模型。厚度（挤出深度）≥ 按钮宽度的 35%，侧面比正面暗两档；UI 层透视下侧面至少露出 6 个美术像素（见 §6b）。
- 正面边缘做 1～2 格的倒角台阶（横平竖直或正 45°），底下接触投影；按下时整体下沉半个厚度、侧面变短，松开回弹。

## 6. UI 不走像素低清（用户 14:00）
「UI 不能和场景一样那么像素低清，关键信息读不明白。」场景默认像素 3×（见 §6b）；**UI 层（血瓶、状态面板、技能槽和技能卡、重投、吟唱按钮、敌人牌、数字、文字）按屏幕原生分辨率清晰渲染**，不进像素低清缓冲。风格仍是刻石与金属、体素造型、带透视，但边缘、图标、数字、中文都要锐利可读。

## 7. 遗物 = 通用底座 + 悬浮模型（用户 16:00：「遗物要有通用的底座，是模型」）
- 左上钱袋下方一排。每件遗物是一个 3D 体素模型，立在**所有遗物共用的同一种底座**上（小石台 + 金属环），模型和底座分两层（同技能按钮）。
- 待机：模型悬浮在底座上方，轻微上下浮动、缓慢自转，投影落在台面。
- 触发：台面金环亮起、光柱升起，模型抬高放大冒光点 → 飞向目标（武器 / 英雄 / 敌人）带光尾 → 生效后飞回底座。
- 冷却 / 用完：模型和底座一起变暗；冷却结束时金环亮一下。
- 点遗物弹 tips（名称 + 一句效果）。原型 3 件：贪婪之手（金手）、铁壁护符（盾牌护符）、战场急救（急救箱）。

## 8. v4 三职业机制的界面表现（Figma 泳道 4～6，用户要求「完整在 UX 里表现出来」）
原则：**不加新操作**，新机制全部用角标、图形、形态表达。
### 刺客 · 连击（4.0～4.4）
- **头顶 5 把小匕首 = 刀鞘 = 本回合还能出几刀**（用户：「满连击看起来像很牛逼的终结，但实际语义是限制」→「刀刃反过来消失」）。回合开始 5 把实刀；每出一刀抽走一把（从右往左），留下虚线空槽，刀只减不增。剩 1 把时这把描橙边、轻闪 = 末刀。0 把 = 刀鞘全灰 + 灰色小字「刀尽」，**不放金光、不飘「满连击」**——上限不是奖励。连击加成不画在刀鞘旁，只在出牌按钮旁的匕首牌上。觉醒「无尽连斩」= 刀鞘多一个槽。
- 末刀提示：`lastStrike` 为真时，按钮旁的匕首牌变橙色写「末刀 +80%」，提醒「这刀打完回合结束，把最大的牌型留到这一刀」。刀用尽时手里剩的暗影骰原地化烟消散。这回合最响的一下给第 5 刀本身（伤害数字最大、顿帧最长），而不是给「到上限」这件事。
- 刀鞘槽数 = 当前出手上限，会随成长变（开局约 3，最多 6，数值待定）。拿到「刀鞘 +1」时：头顶刀鞘右端锻出一个新槽、一把新匕首滑进去、闪一下，这是正向反馈；回合内的耗尽仍然保持安静。
- 技能槽右上角「补骰角标」：小暗影骰 + 数字（袖箭 +1→+2→+3 随当前刀数实时变；影步 = 交几补几）；背刺、影舞是「收尾」旗子角标（不补骰）。
- 选中骰子时，英雄手边浮出将要补回来的暗影骰虚影（补骰预览），出手后真骰从英雄脚下的影子里冒出来落到场上（暗紫色，当回合可用，回合末消散）。不从刀鞘里出，刀鞘只减不增。
- 出牌按钮右上角同样带补骰 / 收尾角标；第 N 刀的加成用一个小匕首牌（+60%）挂在按钮旁，按钮数值已含加成。第一刀后重投灯重新亮一盏 + 小影子闪光。没骰子 / 没合法出手自动结束。
### 魔导 · 蓄星（5.0～5.3）
- 没用掉的骰子留在场上（青色光圈），每回合开始从悬浮区补 1 颗扔进来，最多 6 颗；头顶吟唱环 3 格 = 手里第 4～6 颗；不释放的回合有屏障罩，骰子越多越厚。
- 出牌按钮上方挂「施法类型」标记：交 ≤3 颗 = 蓝色「小咒」+ 循环图标（放完照样吟唱）；交 ≥4 颗 = 金色「释放」+ 迸发图标（释放后环清空、反噬清零）。
- 闪电链 3 颗 = 小咒 + 充能：角标「+1」带下回合箭头，悬浮区提前出现那颗骰子的虚影。
### 狂战 · 斩或挡（6.0～6.3）
- **散骰是排他的牌型**（用户：「散骰就是散骰，是一种牌型，而不是说我选了一个成牌型的骰子也出现可以打散骰的选项」）：选中的骰子整体不成同点 / 连环 / 阵列才算散骰。狂战的散骰（1～3 颗）有两条路：选成散骰时「劈砍」（伤害）和「铁壁」（护甲，数值旁盾牌小图标）两个中号按钮并排，这就是「斩或挡」的选择。选中一对 4 是同点，只出顺劈斩。散骰徽章用「一小把骰子」（组件 `牌型/散骰·1～3颗`），和魔导、刺客只能交 1 颗的单颗徽章区分。见 Figma 6.0。
- 斩杀线：看攻击技能时，目标血条上叠出预计伤害段，够打死就出现骷髅标记。
- 完防线：狂战头顶一条护甲条 + 红色刻度（敌人这回合的攻击），护甲盖过刻度亮绿勾。
- 斩杀再动：打死敌人 → 英雄手边落下红色怒火骰，技能栏上方亮「再动 +1」，回合继续。
- 卖血：重投按钮血红 + 血滴代价；血瓶上本回合卖掉的血画成一截虚线「待还」，做到斩首或完防时回合末流回瓶里（返还比例待模拟定）。完防：盾牌闪光、伤害 0、悬浮区凝出下回合的 +1 骰。
### 敌人站位（去掉距离之后）
- 敌人没有「逼近」意图和逼近步。开场从场地远端走进站位（入场演出），站位整体拉近英雄（现在英雄到敌人约 6～7 个单位，太远），近战攻击时冲到英雄面前、远程原地出手，靠动作区分近战和远程。
- **镜头按敌人大小取景**（用户：「遇到大型敌人的时候镜头得要再高一些，确保可以显示完整敌人」）：所有敌人连同头顶敌人牌完整落在上沿安全区和 HUD 底带之间，英雄也完整入画；俯角约 40°，大型敌人时可到 45° 并拉高。只在入场、召唤或新一波、大型敌人死亡时缓动重取景（约 0.6 秒）；选骰、瞄准、骰子停在场上时镜头不动。

## 6b. 高清像素规范（用户：「UI 在绘制上缺乏了像素感，我要的是高清，风格上还是要靠一些像素绘制的规范——正常的像素内容一个方块 1 个像素，高清的就是 1 个方块 100 个像素」）
- UI 有一个统一的**美术像素**单位 u：1280×720 参考下 u = 3 参考像素，运行时 u = 取整(3 × 屏幕高 / 720) 个屏幕像素（整数，保证锐利）。所有 UI 美术都画在 u 的格子上：96 宽的按钮 = 32 个美术像素。
- 规范：边只走横平竖直或正 45°（1:1 台阶），不要弧线和抗锯齿斜边；不用渐变，用 2～4 档平涂明暗；描边 1u 深色，高光 1u；倒角 1～2u；发光做成 2～3 圈阶梯光，不用柔光晕（特效除外）。
- 3D UI 模型就是「挤出的像素画」：每个体素 = 1 个美术像素（静止时正对屏幕的尺寸），所以 3D 和像素规范是同一套格子。技能图标、遗物、徽章也按这个体素尺寸。
- **文字和数字保持高清字体**（用户之前说过 UI 字体不用那么像素），只加 1u 深色描边和 1u 投影，让它们和像素 UI 搭得上。
- 场景默认改成像素 3×（用户：「这种清晰度的 UI + 3x 效果还不错」），UI 仍按原生分辨率单独渲染。
