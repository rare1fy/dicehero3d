## 一、确认结果（2026-11-12）

| # | 事项 | 结论 |

| 1 | 「v5 的骰子」是不是参考页 A 组那一套 | **待你看过后确认。** A 组就是旧链接 9Mp6… 里最后那一版（v5）的骰子。不影响第 2、3 步，第 4 步迁骰子之前确认即可。 |

## 三、工程结构（第 2 步搭建）

```
dicehero3d/
  package.json        vite + typescript；three 和 pxui 用同一个固定版本（0.162.0），cannon-es 0.20.0，全部打包，不走 CDN
  src/
    core/             纯规则：数据、牌型、结算、遗物、敌人 AI、骰堆、机器人。只输出战斗事件，可单测
    present/
      stage/          演出队列：按事件排演出，每个效果都有蓄力 → 命中 → 余韵
      director/       镜头导演
      dice/ relics/ fx/ text3d/ world/
      looks/A|B|C/    外观包：渲染和光影、角色、场景、骰子材质、特效配色、UI 主题
    ui/               pxui 布局和绑定
    audio/  platform/  debug/
  tests/              规则单测、骰堆测试（迁自 piles_test.mjs）、机器人整场自动打
  tools/              cap.mjs（录屏截图）、sheet.py（拼图）、构建脚本
```

开关：`?look=A|B|C` 切画面方向；每项表现强化单独一个开关（如 `?cam=director|v6`），对比确认后再转正。

## 四、执行顺序（照阶段文档）

1. **参考对照 + 本计划**：已确认（2026-11-12）。
2. **搭工程**：Vite + TS + three / cannon-es，初始化 git，接 pxui 运行时和 platform 层；出浏览器单文件构建，小游戏构建先保证能编译。
3. **迁规则层**：单测加上 piles 用例，机器人打完整场巫妖战、零报错。
4. **迁定稿模块**：骰子交互和演出、遗物、战斗反馈、结算文字、状态特效。先用一套中性的临时外观跑通，再和 v5 / v6 参考片逐项对比，不能有退步。
5. **画面方向**：同一场战斗做 3 个差异明显的外观包，同一时刻、同一镜头并排截图和录屏给你挑。
6. **镜头导演、演出队列、音频**：每项强化都放在开关后面。
7. **自测后给你看**：三个尺寸截图、关键时刻录屏、逐条核对历史问题清单、查 draw call / 帧率 / 包体，发布到同一个私有链接，CLAUDE.md 登记并打 tag。

## 五、录参考时发现的问题（迁移时一并处理）

- **v5 骰面朝向错误**：A3 里选一对 5，升起后显示 4 和 6；B1 里选一对 3，显示 5 和横躺的 3。迁移时用 v6 的骰面朝向检查（`07_qa.js` 的 faceCheck）作为自动测试。
- **v5 手机竖屏下骰子太小**：412 宽时骰子只有约 25px，而且英雄头顶的血条牌压在骰子上。新镜头要保证骰子点数一眼可读，信息牌避让骰子。
- **v5 的符文圈落点**：已按确认 2 处理。
- **工具**：本机 GPU 目前被一个 Python 计算任务占满（应该是你在跑的语音生成），实时帧率在 15–60fps 之间波动。所以录屏改成虚拟时钟逐帧录制，片子里的节奏是准确的原速。参考片都没有声音。
